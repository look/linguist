# Linguist (in Rust)

This is a Rust port of GitHub's [linguist](https://github.com/github-linguist/linguist) project with a narrower focus. For a file path and content, it supports detecting:

- **language** (and associated language metadata like type, color, tm_scope, etc)
- **is_vendored**—Is the file vendored from another library or repository?
- **is_generated**—Is the file generated by a tool and unlikely to be designed for humans to edit (or even read).
- **is_indexable**—Is the file suitable for indexing by the blackbird search engine.

The library leverages the standard linguist yml files for language definitions and heurstics, but it has a few differences from how linguist detects languages:
1. It doesn't use the bayesian classifier. This classifier is slow and cpu intensive and doesn't make sense to run for our application. Files that can only be detected by the bayesian classifier will not be accurately categorized by this library.
2. It only uses regular expressions supported by Rust's regex library which allows for the following guarantees:
   - all regex searches execute in linear time with respect to the size of the regular expression and search text.
   - running user content through this library is safe.

   However, this does mean that a small number of heuristics do not run and files with ambiguous extensions may not be classified properly.
3. It only supports UTF-8 encoded files. This is due to the fact that blackbird also only supports UTF-8.

There is a list of unsupported sample files in [`test/skips_not_supported.txt`](test/skips_not_supported.txt).

In addition, the following linguist features are not supported
- Language breakdown stats
- Iterating files, directories, or Git repos.

## Dependencies

See [Cargo.toml](Cargo.toml) for the full list of dependencies. The intent is to have a very minimal list:

- [once_cell](https://crates.io/crates/once_cell) - for lazy static initialization
- [regex](https://crates.io/crates/regex) - for regular expression matching
- [serde_yaml](https://crates.io/crates/serde_yaml) - for parsing the linguist yml files

## Vendoring Linguist

We depend on a number of linguist yml files for language definitions and heuristics and must keep in sync with the upstream project. In addition, we run unit tests against the linguist samples directory to ensure detection parity.

To sync with linguist, run the following command:

```sh
script/sync [path/to/linguist]
```

This will copy over the requisite yaml files, and pull over the samples and fixtures for testing.
